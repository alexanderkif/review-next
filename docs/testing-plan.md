# Автоматизированные тесты

Тестовый набор намеренно не использует и не требует отдельную тестовую БД. Ни один E2E-тест не входит в production базу, не читает и не изменяет реальные данные.

## Наборы и команды

| Набор | Объём | Зависимости |
|---|---:|---|
| Vitest unit | 74 теста | Нет БД и внешних сервисов |
| Vitest integration | 26 тестов | DB/auth/email и прочие сервисы замоканы |
| Playwright E2E | 4 сценария | Chromium; приложение работает с принудительно отключённым доступом к БД |

```powershell
npm test
npm run test:unit
npm run test:integration
npm run test:coverage
npm run test:e2e
npm run test:e2e:install
npx tsc --noEmit
npm run lint
```

Для Playwright достаточно один раз установить Chromium через `npm run test:e2e:install`. Тестовый сервер сам собирает production build в отдельную `.next-e2e` папку и запускает приложение на `http://127.0.0.1:3100`. Обычная `.next` папка и запущенный dev server не затрагиваются; БД-секреты и реальные учётные данные не нужны.

## E2E без БД

Playwright конфигурация сама выставляет `E2E_NO_DATABASE=1` и подставляет URL `127.0.0.1:1` — локальный недоступный адрес, а не база. Серверный скрипт отказывается запускаться, если эти значения не соответствуют ожидаемым. В этом режиме чтение CV и публичных проектов возвращает пустые данные; запросы к PostgreSQL для этих страниц не выполняются.

E2E-проверки покрывают:

1. Главная показывает корректное пустое состояние CV.
2. Страница проектов загружается с пустым набором и не имеет горизонтального переполнения при прокрутке.
3. Неизвестный ID проекта отображает страницу 404.
4. Форма входа показывает ошибки пустых полей и не отправляет auth-запрос.

Проверки авторизации с настоящим аккаунтом, проекта с реальными данными, загрузки/изменения записей и SQL не относятся к этому проекту тестирования и удалены из E2E-набора. Если в будущем потребуется E2E для таких потоков, это будет отдельное решение; текущий набор от тестовой БД не зависит.

## Vitest-покрытие

- Callback path и централизованные Zod-схемы API.
- Image validation и FileReader/Canvas/Image сценарии.
- HTML escaping писем и ошибка отправки.
- Login form, like button, confirmation dialog.
- Admin API, регистрация, права на комментарии и email verification через замоканные зависимости.

Последняя подтверждённая проверка: 100/100 Vitest тестов, 11 файлов; `image-utils.ts` — 100% statements/lines и 91.42% branches; TypeScript, ESLint и форматирование изменённых файлов проходят.
